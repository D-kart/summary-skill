## 三档覆盖状态

| 状态 | 判定标准 | 符号 |
|---|---|---|
| **✓ 已访到** | 该维度有≥1 条关键事实被讨论，且包含可量化或可定性的具体内容 | `✓` |
| **◐ 部分访到** | 该维度被提及但缺关键细节（如"提到收入但没给数字" / "提到股权结构但没给比例"） | `◐` |
| **✗ 未访到** | 该维度在访谈中**完全没出现** | `✗` |

## 判定细则（避免误判）

### 行业类

| 维度 | ✓ 判定条件 | 易误判为 ◐ 的情况 |
|---|---|---|
| 1.1 主营业务 | 公司主营有清晰描述（做什么 / 卖给谁） | 只说"做新能源"过于宽泛 → ◐ |
| 1.2 市场痛点 & 市场规模 | 同时讲清楚痛点 + 市场规模数字 | 只讲痛点不讲规模 → ◐ |
| 1.3 竞争格局及发展趋势 | 提名 ≥2 个具体竞品 + 行业趋势判断 | 只说"行业很卷"无具体竞品 → ◐ |
| 1.4 公司竞争优劣势 | 至少 2 条优势 + 1 条劣势的具体描述 | 只讲优势不讲劣势 → ◐ |

### 团队类

| 维度 | ✓ 判定条件 |
|---|---|
| 2.1 实控人履历 | 完整时间线（过往公司 / 角色 / 时长） |
| 2.2 管理层其他人员 | 至少 2 位高管（CTO / COO / CFO 等）的姓名 + 履历 |
| 2.3 员工构成 | 总数 + 至少一个维度的占比（研发 / 销售等） |
| 2.4 股权结构 | 主要股东 + **具体持股比例** |
| 2.5 公司战略目标 | 可量化的中长期目标（不是"做大做强"） |

### 产品业务类

| 维度 | ✓ 判定条件 |
|---|---|
| 3.1 业务构成 & 市场策略 | 各业务线的收入占比 + 渠道策略 |
| 3.2 技术原理及发展趋势 | 核心技术路线 + 与竞品的技术差异 |
| 3.3 产品研发规划 | 未来 12 个月的具体里程碑 |
| 3.4 产能情况 | 当前 / 在建 / 规划产能的具体数字 |
| 3.5 供应链 & 客户情况 | TOP 客户名单 + TOP 供应商 |

### 财务及融资类

| 维度 | ✓ 判定条件 |
|---|---|
| 4.1 历史收入 / 收入预测 / 行业占比 | 三项都有数字 |
| 4.2 毛利率 & 净利率 | 两项都有具体百分比 |
| 4.3 上轮融资 | 时间 + 估值（投前/投后）+ 金额 + 投资方 |
| 4.4 本轮融资计划 | 拟融金额 + 估值预期 + 资金用途 |
| 4.5 上市规划 & 中介 / 对赌 | 目标交易所 + 中介机构名单 + 对赌条款（或明确表示无） |

### 风险类

| 维度 | ✓ 判定条件 |
|---|---|
| 5.1 主要风险 | 至少 3 类风险的具体描述（如人员 / 客户集中度 / 供应链 / 政策 / 技术路线等） |

## 核查执行流程

### 步骤 ① 遍历主题块，建立映射
对每个已归并的主题，判断其覆盖了 20 项中的哪些维度，建立映射：

```yaml
coverage:
  - dim_id: "1.1"
    dim_name: "主营业务"
    status: "✓"
    evidence_topic: "公司定位与产品"
    note: ""
  - dim_id: "1.3"
    dim_name: "竞争格局及发展趋势"
    status: "◐"
    evidence_topic: "竞争格局"
    note: "提到 2 家竞品但未给市场份额数据"
  - dim_id: "5.1"
    dim_name: "主要风险"
    status: "✗"
    evidence_topic: null
    note: "本次访谈未涉及风险话题"
```

### 步骤 ② 生成覆盖度核查表
按 `assets/templates/minutes-md-template.md` 的表格格式填充。

### 步骤 ③ 生成"待确认问题清单"
按 `assets/templates/question-checklist-template.md` 的骨架：

- ✓ 已访到：**保留该项条目**，状态注明"本次已访到，纪要位置 → 主题：xxx"。
- ◐ 部分访到：列出**补充追问问题**（根据缺什么补什么）。
- ✗ 未访到：列出**完整候选问题**（参考骨架文件中的标准问题模板）。

### 步骤 ④ 优先级分级
末尾加优先级建议：

- 🔴 **必须下轮访到**：所有 ✗ 项
- 🟡 **建议下轮加深**：所有 ◐ 项
- 🟢 **可选补充**：✓ 项中深度不足的（典型如"主营业务"已访到但未量化）

## 完成标志

- 覆盖度核查表 **20 行齐全**，无遗漏。
- 每行都有明确状态符号（✓ / ◐ / ✗），无空白。
- ✓ 项关联到具体主题块名称。
- ◐ 项注明"缺什么"。
- ✗ 项注明"建议下轮追问"。
- "待确认问题清单"按 5 大类分组，含优先级建议。

## 兜底原则

- 若某项"特殊行业不适用"（如纯研发型早期公司无产能），状态标 `N/A`，note 写明原因。
- 若全部 20 项均 ✓，待确认问题清单的"优先级建议"段写："本次访谈 5 大类 20 小项已全覆盖，无新增追问，建议进入下一阶段（尽调 / 投资备忘录）。"

➡️ **下一步**：调用 `assets/templates/` 下的模板，组装最终的 Markdown 纪要 + docx 排版规范 + 待确认问题清单**三件套**输出。
