# Step 3 · 时间戳标注 SOP

> 三档时间戳分级。docx 模板里的硬性规范，必须 100% 对齐。

## 三档分级

| 档位 | 用途 | 格式 |
|---|---|---|
| **首次出现** | 主题块标题 | `### 主题：{主题名}（首次出现 HH:MM:SS）` |
| **后文补充** | 同主题在对话后期的新增内容 | `（后文补充 HH:MM:SS）{内容}` |
| **时间待核查** | 无法确定准确时间的兜底 | `（时间待核查，最可能区间 HH:MM:SS－HH:MM:SS）` |

## 硬性规则

### 规则 1：主题标题旁必须有时间戳
- 格式严格：`### 主题：{主题名}（首次出现 HH:MM:SS）`
- 全角括号 `（）`不是半角 `()` ← 对齐 docx 模板原版
- 时间戳格式 `HH:MM:SS`，秒位必填，没有秒时补 `00`

### 规则 2：后文补充时间戳必须显式
- 格式严格：`（后文补充 HH:MM:SS）`
- ❌ 不允许写成 `（后文补充）`（缺时间戳）
- ❌ 不允许写成 `后文 00:08:00 补充`（语法不对齐）

### 规则 3：转写无时间戳时的兜底
- 若原始转写**完全没有时间戳**：
  - 所有主题块标题写 `（时间戳缺失）`
  - 不强行编造时间戳
  - 在最末尾"复核说明"加一句："原始转写未提供时间戳，本纪要按对话顺序排列，无具体时间标注。"
- 若原始转写**部分有时间戳**：
  - 有时间戳的主题正常标注
  - 无时间戳的主题写 `（时间待核查，参考前后文约 HH:MM:SS）`

### 规则 4：时间戳必须可验证
- 时间戳来源必须是转写文本中真实存在的时间标记。
- 不要"按对话长度估算"——除非用户明确允许。
- 估算的时间戳必须用 `（时间待核查）` 兜底，不可冒充已确认。

## 时间戳归一化（多种原始格式 → 统一格式）

输入可能的格式：

| 原始格式 | 归一化后 |
|---|---|
| `00:00:19` | `00:00:19`（已是目标格式） |
| `0:19` | `00:00:19`（补全小时） |
| `19s` | `00:00:19` |
| `[00:19]` | `00:00:19` |
| `00分19秒` | `00:00:19` |
| `第3分钟` | `00:03:00`（估算，需打 `（时间待核查）`） |
| `开头`/`一开始` | `（时间待核查，参考 00:00:00 起）` |
| `最后`/`末尾` | `（时间待核查，参考末段）` |

## 与 docx 模板原版的对齐

用户原版 docx 模板中的示例：

```
### 主题：产品价格与系统成本（首次出现 00:24:45）
**内容**：
- 原计划锂电池价格较优惠。
- 一个电池包一度电成本一两千元……
- 安全要求高。

### 主题：大储市场机会（首次出现 00:35:41）
**内容**：
- （00:01:44起）现有储能约二三百GWh……
- （后文补充 00:08:00）电芯尺寸：314为200×170mm……
- （后文补充 00:30:43）海辰生产主要在厦门、重庆……
```

⚠️ 注意"大储市场机会"主题的 `first_appear` 是 `00:35:41`，但其内部 `（00:01:44起）` 是更早时间——这是因为 `00:01:44` 是该话题在主题被首次"明确命名"前的零散提及，主题块的归并位置以"明确成为讨论焦点"的时间为准。

## 时间戳排查清单

完成纪要后必须做的最后核查：

- [ ] 每个 `### 主题：` 后是否都带了 `（首次出现 HH:MM:SS）` 或 `（时间戳缺失）`？
- [ ] 所有"后文补充"是否都有具体 `HH:MM:SS`？
- [ ] 所有"时间待核查"是否给出了最可能区间或参考位置？
- [ ] 主题块按 `first_appear` 时间升序排列？
- [ ] 时间戳格式统一为 `HH:MM:SS`？（无 `HH:MM` 或 `MM:SS`）
